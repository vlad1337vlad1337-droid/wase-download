# Release audit, 2026-10-02

## Published product

https://wase.download/ serves static EN/RU/ZH pages and a private Node/Docker conversion broker. Both root and www DNS return 150.251.143.215 without the Cloudflare proxy. The public website accepts TLS 1.2; a forced TLS 1.3 website handshake is rejected. The certificate covers both names; www redirects to the canonical root. Certificate renewal reloads nginx.

The tool groups 915 declared input extensions into ten categories. These declarations do not guarantee every engine pair or arbitrary file. Server input limit: 100 MB; batch: 20 files; output: 200 MB. Browser fallback supports images with a 20 MB limit. ZIP/TAR repacking and font conversion are local; 7Z/RAR repacking is not implemented. Photographic vectorization approximates pixels rather than recovering original design geometry.

## Fixed defects

- The container attempted chmod on the broker-owned mounted input/root, causing valid Linux conversions to return 422. Only converter-owned outputs now have their permissions adjusted.
- A file selected before the format catalogue arrived could enter the wrong processing mode. File selection is captured before awaiting readiness; an early TXT upload now produces a downloadable PDF.
- Upstream presentation input support was incomplete. Explicit LibreOffice Impress conversions now provide PPT/PPTX/ODP to PDF/PPTX/ODP.
- Completed jobs now release their concurrency slot before replying. Two simultaneous visitors queue instead of receiving a false busy response.
- Uploads stream to temporary disk; conversion runs offline with a read-only root, non-root UID, bounded CPU/memory, output count and timeout.
- Compact landscape layout fits 844×390 without reducing the primary button below 44 pixels.

## Verification

- 34 frontend cases passed in Chromium and mobile WebKit: paste/drop, real browser format bytes, ZIP content, locale/theme, no default tracking, custom menus, responsive widths and short heights, static SEO.
- All 11 server scenarios passed on the public HTTPS deployment across two batches: SVG download, corrupt-file recovery, origin/format rejection, PDF/audio, multi-file ZIP, AVIF tracing, HTML text/archives/fonts/CAD, concurrent queue, early upload, EPUB/presentation round trip, MP4→WebM. Additional public mobile WebKit SVG/early-upload cases passed.
- 10 archive security checks passed, including traversal, absolute paths, duplicates, symlinks, entry-count and expanded-size limits.
- Runtime dependencies: npm audit --omit=dev reports zero vulnerabilities.
- After tests, verify no wase-job directories or converter containers remain; API/nginx must be active.

Automated WebKit is not a physical iPhone acceptance test. Search Console, Webmaster and Metrika remain inactive without the actual account verification/counter values. No guarantee of indistinguishability from an ordinary site or immunity to IP blocking is made.

## VPN trial scope

Only Germany, Finland, Poland and Austria primary TCP subscription entries use the new ingress on port 443. Their published profiles passed HTTPS certificate verification, correct country exit IP and 4 MiB download from the existing Russian application server. The other countries and every XHTTP backup profile retain their prior routes. Existing saved client configurations require a subscription refresh. REALITY retains its required TLS behavior; the TLS 1.2 setting above applies to the website.
